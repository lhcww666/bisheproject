# 字段标签与列宽调整说明

## 1. 为什么会出现很长的列名

若依的代码生成器把 MySQL 建表时的列注释（`COMMENT`）直接当作页面标签使用，所以列注释写多长，列表表头和表单标题就跟着多长。

核心版建表脚本 `sql/module_core.sql` 里原本写的是：

```sql
applicant_id BIGINT NOT NULL COMMENT '申请人，对应若依 sys_user.user_id'
```

生成出来的页面标签就是「申请人，对应若依 sys_user.user_id」，在列表里会被挤成三行。这类标签已经统一改成「短标签 + 括号补说明」的写法。

## 2. 现在的命名口径

原则：**标签写给人看，技术细节放括号里**。

| 表.字段 | 原来的列注释 | 现在的列注释 / 页面标签 |
| --- | --- | --- |
| `reservation.applicant_id` | 申请人，对应若依 sys_user.user_id | 申请人ID（若依用户主键 sys_user.user_id） |
| `reservation_review.reviewer_id` | 审核人，对应若依 sys_user.user_id | 审核人ID（若依用户主键 sys_user.user_id） |
| `safety_exam_record.student_id` | 学生，对应若依 sys_user.user_id | 学生ID（若依用户主键 sys_user.user_id） |
| `credit_record.user_id` | 用户，对应若依 sys_user.user_id | 用户ID（若依用户主键 sys_user.user_id） |
| `credit_record.change_score` | 变动分值，可正可负 | 变动分值（可正可负） |
| `reservation_device.reservation_id` | 预约主键 | 预约ID |
| `reservation_device.device_id` | 设备主键 | 设备ID |
| `reservation_review.reservation_id` | 预约主键 | 预约ID |
| `device.room_id` | 所属实验室 | 所属实验室ID |
| `room.description` | 说明 | 实验室说明 |

对应的前端修改：

- 列表列名、查询条件标签、表单标签、必填校验提示统一使用上面的短标签。
- 表单里的输入框仍保留完整提示，例如「请输入申请人ID（sys_user.user_id）」，避免看不出要填哪个表的主键。
- 原来的标签「变动分值，可正可负」超出列宽会被截断，现在改为「变动分值」，可正可负的说明放在输入提示里。
- `device/index.vue` 里残留的生成器占位符 `${comment}` 已改回「备注」。
- 列表里「主键」原来写死 50px，四个字被挤成竖排，已去掉固定宽度。
- 后端实体（`Reservation`、`ReservationReview`、`SafetyExamRecord`、`CreditRecord`）的 `@Excel` 列名和 `@NotNull` 提示同步改成短标签，导出的 Excel 表头和接口校验提示不再带 `sys_user.user_id`；技术说明只留在字段的 Javadoc 注释里。

## 3. 已建库怎么同步

新库直接用 `sql/module_core.sql`。如果数据库已经建好，执行 `sql/module/03-field-label-alignment.sql`，用 `ALTER TABLE ... MODIFY COLUMN` 把列注释刷成新口径（只改注释，不动类型和默认值）。下次用代码生成器重新导入表时，标签就会是新写法。

## 4. 表格列宽可以拖

Element Plus 的 `el-table` 自带列宽拖拽能力，但要求表格开启 `border` 属性，否则拖动逻辑不生效。本次给项目里的 `el-table` 统一加上了 `border`：

- 7 个业务页面：`ui/src/views/module/*/index.vue`
- 若依自带的系统、监控、代码生成页面：`ui/src/views/system/*`、`ui/src/views/monitor/*`、`ui/src/views/tool/gen/*`

改完之后，把鼠标放在任意表头单元格的右边界，光标变成左右箭头就能拖动调整列宽；列宽只在当前页面有效，刷新后恢复默认。

顺手统一了导入按钮的文案：`下载模版` → `下载模板`（业务页面里）。
