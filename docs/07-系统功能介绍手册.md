# 校园实验室智能预约与安全管理平台系统功能介绍手册

## 1. 系统定位

本系统面向高校实验室预约与安全管理场景，在传统实验室业务平台之上引入基于 Spring AI 的智能助手。系统首先保证实验室、设备、预约、审核、安全考试、信用分和耗材等业务闭环可以独立运行，再通过受控工具调用和知识库检索为学生、教师和管理员提供自然语言交互能力。

系统不是让大模型直接操作数据库，而是将已有后端业务能力封装为白名单工具。模型负责理解问题和组织回答，Java 业务服务负责身份、权限、数据范围、预约冲突、实验室准入、安全考试、信用分和库存校验。所有工具调用均留有审计记录。

## 2. 建设目标

1. 建立“学生申请、教师审核、学生使用、信用与安全管理”的完整预约闭环。
2. 将实验室准入、安全考试、信用分和设备库存等规则落实到后端事务中。
3. 用 Spring AI Tool Calling 将自然语言问题连接到真实业务数据。
4. 用 RAG 为实验室安全问答和平台使用问答提供可追溯资料。
5. 通过角色化提示词、工具白名单、数据范围和人工确认控制 AI 行为边界。
6. 为管理员提供会话、工具调用、知识库和离线评测管理入口。

## 3. 用户角色

| 角色 | 主要职责 | 典型功能 |
| --- | --- | --- |
| 学生 | 查询本人预约资格并完成实验预约 | 预约申请、我的预约、签到、结束实验、取消预约、安全考试、信用分、违规记录、耗材领用、智能助手 |
| 教师 | 审核本人负责班级的预约 | 待审核预约、学生资质、预约详情、通过/驳回/弃审、班级统计、智能助手 |
| 管理员 | 维护平台资源与规则并检查运行情况 | 实验室、设备、准入规则、班级负责人、安全题库、信用违规、耗材库存、知识库、Agent 审计与评测 |

角色由登录账号的真实角色决定。用户在聊天中声称自己是其他角色，不会改变权限，也不会切换 Agent 工具集。

## 4. 主要功能

### 4.1 登录与角色导航

- 使用若依账号、密码和验证码登录。
- 使用 JWT 维持登录状态，后端通过菜单权限和接口权限共同控制访问。
- 不同角色登录后只看到与自身职责相关的菜单和数据。
- 首页根据角色展示实验室、预约、审核、考试、信用分和违规等统计信息。

### 4.2 实验室与设备档案

- 管理员维护实验室编号、名称、类型、位置、容量、开放时间、安全等级、预约模式和状态。
- 管理员维护设备编号、名称、类型、所属实验室、数量、状态和培训要求。
- 实验室准入可以按院系、班级或具体学生配置。
- 学生预约时通过业务接口选择可用实验室和设备，不直接依赖资源管理菜单。
- 设备可以按台设置预约数量，后端校验设备归属、可用状态和库存数量。

### 4.3 预约与审核闭环

预约流程如下：

```text
查询预约资格
  -> 选择实验室、日期、时段和参与人数
  -> 选择所需设备及数量
  -> 后端检查准入、容量、开放时间、时间冲突、考试和信用分
  -> 低风险预约自动通过，或高风险预约进入待审核
  -> 教师审核通过或驳回
  -> 学生签到
  -> 学生结束实验
```

预约状态包括：

| 状态 | 含义 |
| --- | --- |
| 待审核 | 已提交，等待教师审核 |
| 已通过 | 审核通过或按规则自动通过 |
| 已驳回 | 审核未通过，可以查看审核意见 |
| 已取消 | 学生取消或业务关闭 |
| 已完成 | 已签到并结束实验 |
| 已签到 | 已到达实验室并完成签到 |
| 已爽约 | 超过签到时限未签到 |

系统支持个人预约和班级预约，并对实验室时间重叠、容量、开放时间、设备数量和前端重复提交进行校验。签到、完成、爽约、取消、审核和弃审都会追加状态日志，不覆盖历史记录。

### 4.4 实验室准入

- 管理员可以配置实验室是否开放预约、是否需要审核以及允许预约的院系、班级或个人。
- 学生提交预约时，后端根据当前用户部门和身份检查准入规则。
- 不符合准入规则时，即使时段空闲也不能预约。
- 班级负责人可以代表班级发起班级预约，但仍需通过容量、时间和资格校验。

### 4.5 安全考试

- 学生可以在“安全考试”页面开始随机组卷考试并在线交卷。
- 默认规则为随机 10 题、80 分通过、成绩有效期一年，具体参数可在系统配置中调整。
- 系统保存考试时间、成绩、是否通过和有效期。
- 预约要求安全考试的实验室时，后端检查是否存在有效通过的考试记录。
- 管理员可以维护安全考试题库及其启停状态。

### 4.6 信用分与违规记录

- 每名学生具有信用账户和信用流水。
- 爽约、临近开始取消、安全违规和设备损坏等行为可以形成违规记录。
- 管理员登记违规时可以扣减信用分，撤销违规时可以回补相应分值。
- 学生可以看到本人信用分、变动原因和违规说明。
- 信用分低于当前门槛时，预约工具和预约事务会拒绝新的申请。

### 4.7 耗材领用与库存

- 管理员维护耗材编号、名称、规格、所属实验室、库存、最低库存和启停状态。
- 库存变更必须通过“调整库存”或审核领用产生，并写入库存流水。
- 学生只能针对本人的待审核或已通过预约申请耗材，且耗材必须属于预约实验室。
- 管理员审核通过后扣减库存；库存不足时拒绝通过。
- 预约取消时，待审核领用申请关闭，已通过领用申请归还库存并生成归还流水。
- 低库存耗材在列表中醒目显示，便于管理员补充。

### 4.8 数据看板

- 学生查看本人预约、信用和安全考试相关信息。
- 教师查看本人负责班级的预约与资质概况。
- 管理员查看全校预约、审核、实验室使用、爽约和安全考试等统计。
- 看板使用 ECharts 展示统计结果，统计口径由后端按角色和数据范围计算。

## 5. Spring AI 智能助手

### 5.1 角色化助手

系统根据登录角色自动选择助手：

| 角色 | 助手 | 可以辅助的事务 |
| --- | --- | --- |
| 学生 | 学生预约助手 | 本人资格、考试、信用分、预约记录、当前可约实验室、设备、安全知识、预约草稿 |
| 教师 | 教师审核助手 | 负责班级的待审核预约、预约详情、学生考试和信用资质、班级统计 |
| 管理员 | 平台管理助手 | 全校审核概况、学生资质、平台规则、知识库与运行状态 |

每个角色使用独立系统提示词和独立工具白名单，不能通过前端参数切换角色。

### 5.2 可用自然语言能力

- 查询指定时段或当前时段可预约的实验室。
- 查询实验室可预约设备及数量。
- 查询本人预约、审核意见、安全考试状态和信用分。
- 判断本人是否具备预约资格。
- 回答实验室安全知识，并给出资料标题或来源。
- 回答平台页面、预约流程、设备档案、知识库和考试规则等使用问题。
- 学生提供完整预约条件后生成待确认预约草稿。
- 教师查询待审核预约、预约详情和学生资质，整理审核依据。
- 管理员查询全校范围内的审核概况和学生资质。

### 5.3 写操作边界

- 模型不能直接执行预约提交、预约取消、教师审核、信用调整或库存变更。
- 学生只能生成预约草稿，必须在预约页点击“确认提交预约”后才真正提交。
- 教师只能获得审核依据，必须在预约审核页点击通过、驳回或弃审完成最终操作。
- 管理员不能通过助手代替人工执行审核。
- 用户身份一律从后端登录上下文获取，不能由模型或请求参数指定。

### 5.4 RAG 知识问答

- 知识库包含实验室安全知识和平台使用帮助两类内容。
- 每篇知识文档可以设置全部角色、学生、教师或管理员可见范围。
- 检索同时使用中文关键词、TF-IDF、结构匹配和本地特征哈希向量计算。
- 检索结果带文档标题和片段内容，模型应依据检索结果回答，减少无依据生成。
- 页面提供“知识库”入口，可以在不调用大模型的情况下直接检查召回结果。
- 管理员可以在“Agent知识库”中维护文档、片段、关键词、类型、可见范围和启停状态。

### 5.5 会话、流式回复和消息审计

- 每个用户拥有自己的会话列表，不能读取其他用户的会话。
- 支持新建、切换、删除会话，并保存历史消息。
- 前端使用 SSE 流式接收回复，同时保留同步接口作为兼容路径。
- 助手回复可以展示本次参考的业务数据和工具调用摘要；完整技术信息仅对管理员展示。
- 工具名称、参数、结果、成功状态、耗时、用户和关联消息会写入审计表。

### 5.6 在线评测与回归评测

- 管理员可以从“Agent评测”页面运行离线规则评测或真实模型评测。
- 评测覆盖意图识别、工具选择、知识召回、角色语气、平台帮助和写操作边界。
- 当前评测基线共 60 条，支持区分开发集与留出集，避免只针对训练问题调参。
- 评测结果包含用例通过情况、工具命中、RAG 命中、回答质量和必要的失败原因。
- 自动化测试覆盖 Agent 路由、工具、知识检索、会话、限流、预约状态机和耗材库存等核心逻辑。

## 6. 安全与可追溯设计

1. **真实身份**：工具始终使用当前 JWT 用户，不接受模型传入的用户身份。
2. **工具白名单**：不同角色只注册允许使用的工具，不能调用未开放能力。
3. **数据范围**：学生仅能查看本人数据，教师仅能查看负责班级数据。
4. **业务复校**：模型生成的参数进入 Java 服务后仍要经过全部业务规则校验。
5. **人工确认**：预约和审核等关键写操作不在模型工具中直接完成。
6. **知识范围**：知识检索按文档类型、启停状态和角色可见范围过滤。
7. **审计记录**：工具调用与预约状态变化均保存操作人和时间。
8. **密钥保护**：DeepSeek Key 只保存在本地被忽略的配置文件或环境变量中，不进入前端响应和 Git。
9. **接口限流**：聊天和模型连接测试接口按来源 IP 限流，降低误用和费用风险。

## 7. 技术特点

- 前端：Vue 3、Vite、Element Plus、Axios、Pinia、ECharts。
- 后端：Spring Boot 3、Spring AI、Spring Security、JWT、MyBatis-Plus。
- 数据：MySQL 8 保存业务与 Agent 数据，Redis 保存登录和验证码等缓存。
- AI：DeepSeek Chat 模型、Spring AI Tool Calling、角色化 ChatClient、RAG 混合检索。
- 工程：前后端分离、Maven 多模块、菜单驱动路由、SQL 可重复执行、GitHub Actions 持续集成。

## 8. 当前实现边界

1. 智能对话依赖可用的 DeepSeek Key 和网络；未配置 Key 时，会话管理、知识库检索、审计和离线评测仍可使用。
2. 当前 RAG 使用 MySQL 数据与本地 TF-IDF/特征哈希向量，不依赖外部向量数据库或外部 Embedding 服务，适合毕业设计部署和离线演示。
3. 系统采用单体应用，适合课程设计和本科毕业设计规模，不等同于高并发生产集群。
4. 预约能否成功以提交和审核时的实时业务校验为准，助手的查询结果不能替代最终事务校验。
5. 系统内置演示数据用于答辩，正式使用前应由管理员清理或替换为真实数据。

## 9. 推荐演示主线

```text
学生登录
  -> 查看首页与预约资格
  -> 打开智能助手查询当前可约实验室
  -> 查询实验室和设备
  -> 生成预约草稿并在预约页确认
  -> 教师登录并查看待审核预约
  -> 查看学生考试与信用资质
  -> 在审核页通过预约
  -> 学生签到并结束实验
  -> 演示耗材领用与库存流水
  -> 管理员查看 Agent 审计、知识库和评测结果
```

这条主线同时展示传统业务闭环、权限隔离、业务规则、工具调用、RAG、人工确认和审计能力。
