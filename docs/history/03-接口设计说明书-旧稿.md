# 校园实验室智能预约与安全管理平台接口设计说明书

## 1. 接口约定

- 基础地址：`/`
- 数据格式：JSON
- 字符编码：UTF-8
- 认证方式：若依 JWT，放在 `Authorization` 请求头
- 成功响应：沿用若依统一响应结构
- 分页参数：`pageNum`、`pageSize`
- 时间格式：`yyyy-MM-dd HH:mm:ss`
- 所有写接口必须进行后端权限和参数校验

## 2. 实验室接口

### 2.1 查询实验室列表

`GET /lab/room/list`

权限：`lab:room:list`

请求参数：`roomName`、`roomType`、`status`、`pageNum`、`pageSize`。

返回字段：`id`、`roomCode`、`roomName`、`roomType`、`location`、`capacity`、`safetyLevel`、`openTime`、`status`。

### 2.2 新增实验室

`POST /lab/room`

权限：`lab:room:add`

请求示例：

```json
{
  "roomCode": "CHEM-A101",
  "roomName": "化学实验室 A101",
  "roomType": "CHEMISTRY",
  "location": "实验楼 A 区 101",
  "capacity": 24,
  "safetyLevel": 2,
  "openTime": "08:00-21:00",
  "status": 1
}
```

### 2.3 修改和停用实验室

`PUT /lab/room`

权限：`lab:room:edit`

`DELETE /lab/room/{id}` 或使用状态修改接口，权限：`lab:room:remove`。已有预约的实验室不建议物理删除，应改为停用。

## 3. 设备接口

### 3.1 查询设备

`GET /lab/device/list`

权限：`lab:device:list`

参数：`roomId`、`deviceName`、`deviceType`、`status`、`pageNum`、`pageSize`。

### 3.2 新增设备

`POST /lab/device`

权限：`lab:device:add`

请求字段：`roomId`、`deviceCode`、`deviceName`、`deviceType`、`quantity`、`status`、`requiresTraining`。

## 4. 预约接口

### 4.1 查询可用实验室

`GET /lab/reservation/available-rooms`

参数：`startTime`、`endTime`、`participantCount`、`deviceIds`。

后端返回满足开放时间、容量、状态和预约冲突条件的实验室列表。

### 4.2 创建预约

`POST /lab/reservation`

权限：`lab:reservation:add`

请求示例：

```json
{
  "roomId": 1,
  "experimentName": "有机溶剂萃取",
  "startTime": "2026-09-16 14:00:00",
  "endTime": "2026-09-16 16:00:00",
  "participantCount": 2,
  "deviceIds": [3],
  "remark": "需要使用离心机"
}
```

后端从登录用户上下文获取申请人 ID，不允许使用请求体中的 `applicantId`。返回预约编号、状态和是否需要审核。

### 4.3 查询我的预约

`GET /lab/reservation/my`

权限：`lab:reservation:my`

参数：`status`、`startTime`、`endTime`、`pageNum`、`pageSize`。只能返回当前登录学生自己的预约。

### 4.4 取消预约

`POST /lab/reservation/{id}/cancel`

权限：`lab:reservation:cancel`

后端必须检查预约归属、当前状态和取消时间限制。

## 5. 审核接口

### 5.1 待审核列表

`GET /lab/review/pending`

权限：`lab:reservation:review`

返回申请人、实验室、时间、实验内容、风险等级、安全考试状态、信用分和当前状态。

### 5.2 审核预约

`POST /lab/review/{reservationId}`

权限：`lab:reservation:review`

请求示例：

```json
{
  "result": "APPROVED",
  "comment": "请按要求佩戴护目镜"
}
```

审核人 ID 从登录上下文取得；驳回时 `comment` 必填；已审核预约不能重复审核。

## 6. 安全考试与信用分接口

`GET /lab/safety/status`：查询当前学生安全考试状态。

`GET /lab/safety/questions`：获取考试题目，不返回标准答案。

`POST /lab/safety/submit`：提交考试答案，后端计算成绩并保存记录。

`GET /lab/credit/current`：查询当前信用分。

`GET /lab/credit/records`：查询当前用户信用分流水；管理员可按用户查询。

## 7. Agent 工具接口（二期）

Agent 工具不是开放给浏览器的普通接口，而是后端内部受控方法：

| 工具 | 作用 | 是否写操作 |
| --- | --- | --- |
| `queryAvailableRooms` | 查询时间段内可用实验室 | 否 |
| `queryAvailableDevices` | 查询设备 | 否 |
| `checkSafetyExamStatus` | 查询安全考试 | 否 |
| `queryStudentCredit` | 查询信用分 | 否 |
| `queryMyReservations` | 查询本人预约 | 否 |
| `createReservationDraft` | 生成预约草稿 | 否/临时数据 |
| `confirmReservation` | 用户确认后创建预约 | 是 |
| `cancelReservation` | 取消本人预约 | 是 |

所有工具必须从当前登录上下文取得用户身份，写工具必须再次调用预约 Service 完成完整业务校验。

## 8. 接口测试要求

每个接口至少测试：正常参数、缺少参数、非法 ID、无权限用户、重复提交、越权访问和数据库异常。预约接口必须覆盖时间冲突、容量超限、考试未通过、信用分不足和设备停用等场景。
