# 校园实验室智能预约与安全管理平台系统概要设计说明书

## 1. 设计目标

系统采用前后端分离的单体架构，优先实现稳定、易理解、便于答辩的实验室业务闭环。通用能力复用若依，业务能力集中在实验室模块，AI 作为后续智能交互层接入既有业务接口。

## 2. 系统架构

```text
Vue 3 + Element Plus
        |
        | RESTful API / JWT
        v
Spring Boot 3 + RuoYi
  |- ruoyi-admin      启动模块
  |- ruoyi-framework  权限、JWT、异常和基础配置
  |- ruoyi-system     用户、角色、菜单和系统功能
  |- ruoyi-biz         实验室、设备、预约、安全业务
  `- ruoyi-common      通用工具和基础对象
        |
        +--> MySQL：业务与权限数据
        `--> Redis：令牌、缓存和登录相关数据
```

二期 AI 架构：

```text
用户自然语言
   -> 前端聊天页面
   -> Agent 服务
   -> 意图识别和参数抽取
   -> 白名单 Java Tool
   -> 业务 Service
   -> MySQL / 知识库
```

## 3. 模块设计

### 3.1 实验室模块

建议在 `ruoyi-biz` 中建立以下包结构：

```text
com.ruoyi.biz.lab
├── controller
├── service
│   └── impl
├── mapper
├── domain
├── enums
└── validation
```

实验室、设备、预约、审核、安全考试和信用分可以先放在同一个 `lab` 业务域中，等功能稳定后再按模块拆分。

### 3.2 分层职责

| 层 | 职责 |
| --- | --- |
| Controller | 接收请求、校验参数、返回统一结果，不编写复杂业务。 |
| Service | 实现预约规则、冲突检测、状态流转和事务。 |
| Mapper | 使用 MyBatis-Plus 或 MyBatis 访问数据库。 |
| Domain | 保存实体、查询对象、提交对象和返回对象。 |
| Enum | 集中管理预约状态、实验室状态和风险等级。 |
| Validation | 处理时间、人数、容量和资格等业务校验。 |

## 4. 数据设计

正式接入若依时，直接使用若依已有的 `sys_user`、`sys_role`、`sys_menu` 等表。实验室业务只新增以下表：

| 表 | 作用 |
| --- | --- |
| `lab_room` | 实验室基本资料 |
| `lab_device` | 设备资料和状态 |
| `lab_reservation` | 预约申请和状态 |
| `reservation_device` | 预约与设备关系 |
| `reservation_review` | 教师审核记录 |
| `safety_exam_record` | 安全考试成绩和有效期 |
| `credit_record` | 信用分流水 |

所有业务表建议包含 `id`、`created_at`、`updated_at` 等通用字段；外键字段引用若依用户主键。数据库脚本应先在开发库验证，再纳入项目版本管理。

## 5. 关键业务设计

### 5.1 预约事务

预约创建必须使用事务：

1. 校验登录用户和角色。
2. 校验开始时间早于结束时间，时间不能早于当前时间。
3. 查询实验室状态、开放时间和容量。
4. 查询同一实验室的重叠有效预约。
5. 查询设备状态和数量。
6. 查询安全考试有效期与信用分。
7. 根据风险等级决定是否审核。
8. 生成预约编号并保存主表和设备关联表。

冲突检查与保存必须在同一事务中完成；高并发场景可增加数据库锁或唯一业务约束。毕业设计阶段至少要通过串行和重复提交测试。

### 5.2 状态流转

状态只允许按业务规则流转，禁止前端直接传入任意状态：

```text
PENDING -> APPROVED
PENDING -> REJECTED
PENDING -> CANCELED
APPROVED -> CANCELED
APPROVED -> COMPLETED
```

### 5.3 Agent 安全边界

Agent 工具只接收必要参数，用户身份从后端登录上下文取得。查询工具可返回当前用户授权范围内的数据；创建和取消预约属于写操作，必须先生成草稿，再展示给用户确认，最后由后端重新执行权限、冲突和资格校验。

## 6. 前端页面设计

前端目录建议：

```text
ui/src
├── api/lab
├── views/lab/room
├── views/lab/device
├── views/lab/reservation
├── views/lab/review
├── views/lab/safety
└── views/lab/assistant
```

第一期页面：实验室列表、设备管理、预约申请、我的预约、教师审核、安全考试。每个页面遵循若依现有列表页、查询栏、表格、分页、弹窗表单和权限按钮模式。

## 7. 异常处理

统一返回业务错误码和用户可理解的消息，例如：

| 错误场景 | 建议提示 |
| --- | --- |
| 时间冲突 | 该实验室在所选时间段已有预约，请选择其他时间。 |
| 容量超限 | 参与人数超过实验室可容纳人数。 |
| 考试未通过 | 预约高风险实验前请先通过安全考试。 |
| 信用分不足 | 当前信用分不足，暂不能提交该预约。 |
| 无权限 | 当前账号没有执行该操作的权限。 |

## 8. 部署设计

开发环境：JDK 21、Maven、MySQL 8、Redis、Node.js 22。后端默认端口 8087，前端开发服务器默认使用 Vite 分配的端口，当前为 8090。生产部署时可使用 Nginx 代理前端静态资源和后端 API。
