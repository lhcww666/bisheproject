# 校园实验室智能预约与安全管理平台操作手册

## 1. 手册说明

本手册面向系统的学生、教师和管理员使用者，说明常用入口、操作步骤和注意事项。开发环境安装、数据库脚本和代码生成流程见 `docs/04-本地开发指导书.md` 与 `docs/05-代码生成与模块落地说明.md`。

## 2. 登录系统

1. 在浏览器打开管理员提供的系统地址。本地开发通常为 `http://127.0.0.1:8090/admin/`。
2. 输入用户名、密码和验证码。
3. 点击登录。
4. 如果页面提示验证码错误，刷新验证码后重试。
5. 登录后首页菜单由当前角色权限决定，看不到某项菜单通常表示该账号没有对应权限。

演示账号可以使用 `admin`、`stu101`、`teacher101` 等用户名。演示账号密码由本地数据库统一维护，不在本手册和 Git 中保存；需要重置时按本地开发流程在数据库中处理。

## 3. 角色首页

登录后首先进入按角色显示的数据看板。看板卡片和图表用于了解当前账号权限范围内的实验室、预约、审核、签到、爽约、安全考试、信用分和违规情况。

操作建议：

1. 先查看首页统计，确认当前有待审核预约或异常数据。
2. 点击左侧业务菜单进入具体功能。
3. 表格行可以点击进入详情；按钮是否出现取决于账号权限。
4. 页面顶部显示操作说明时，建议先阅读提示，再执行提交、审核或库存调整等操作。

## 4. 学生操作

### 4.1 检查安全考试和预约资格

1. 打开“安全考试”菜单。
2. 查看本人最近考试状态、成绩、是否通过和有效期。
3. 没有有效成绩时，点击“开始考试”。
4. 按题目要求完成全部题目后提交试卷。
5. 达到通过分数且仍在有效期内，才满足需要考试的实验室准入条件。
6. 在“信用分”和“违规记录”中查看本人当前分值及扣分原因。

预约资格由实验室准入、安全考试、信用分、开放时间、容量和预约冲突共同决定，不能只凭其中一项判断。

### 4.2 提交预约

1. 打开预约业务菜单，进入预约申请页面。
2. 点击“新增”或“预约申请”。
3. 选择实验室，确认位置、容量和开放时间。
4. 选择日期、开始时间和结束时间。
5. 填写实验名称和参与人数。
6. 按需选择设备，并为每台设备填写使用数量。
7. 查看系统提示，确认没有准入、容量、冲突或设备数量问题。
8. 点击提交。
9. 需要审核的预约进入“待审核”；低风险实验室按规则可能自动通过。

提交成功后应记录预约编号。页面提示“提交成功”不等同于教师已经审核通过，最终状态以“我的预约”或预约详情为准。

### 4.3 查看审核结果

1. 打开“我的预约”或预约列表。
2. 通过预约编号、实验室、时间或状态筛选。
3. 点击记录行查看预约详情和审核意见。
4. 状态为“已驳回”时，在审核记录中查看驳回原因，按意见修改后重新提交。
5. 状态变化日志会显示预约从提交到取消、审核、签到和完成的过程。

### 4.4 签到和结束实验

1. 预约审核通过后，在允许签到的时间窗口内进入预约列表或详情。
2. 点击“签到”。
3. 系统检查预约状态和签到时间，未到时间或超过时限时会拒绝。
4. 签到成功后状态变为“已签到”。
5. 实验结束后点击“结束实验”，按提示填写实际参与人数。
6. 状态变为“已完成”后，该预约不能再签到。

超过签到时限且未签到的预约会被标记为“已爽约”，并可能产生信用扣分；实际规则以系统提示为准。

### 4.5 取消预约

1. 打开本人预约列表。
2. 找到“待审核”或“已通过”的预约。
3. 点击“取消预约”并确认。
4. 已完成、已完成审核之外的终态预约不能再次取消。
5. 临近开始取消可能产生违规和信用扣分。
6. 关联耗材申请会随预约取消执行关闭或归还。

### 4.6 班级负责人发起班级预约

1. 班级负责人账号在预约页面选择班级预约类型。
2. 确认预约班级和参与人数。
3. 选择实验室、时间和设备。
4. 提交后按普通预约流程等待审核。
5. 班级预约仍受实验室准入、容量、设备数量和安全考试等规则限制。

### 4.7 申请领用耗材

1. 打开“耗材领用”菜单。
2. 点击“申请领用”。
3. 选择本人的待审核或已通过预约。
4. 选择属于预约实验室的耗材。
5. 填写申请数量、用途或领用原因。
6. 提交后等待管理员审核。
7. 在“耗材领用”列表查看状态和审核意见。

申请页面没有可选预约时，先检查预约是否属于本人、是否处于待审核或已通过状态，以及耗材是否属于预约实验室。

## 5. 教师操作

### 5.1 查看待审核预约

1. 使用教师账号登录。
2. 打开“预约审核”菜单。
3. 查看本人负责班级范围内的待审核预约。
4. 点击记录行进入预约详情。
5. 核对实验室、时间、参与人数、设备需求、实验说明、安全考试和信用情况。

教师只能查看由数据范围授权的班级和学生数据。列表为空可能是当前没有待审核预约，也可能是账号未分配负责班级。

### 5.2 通过、驳回或弃审

1. 在预约详情点击“审核”。
2. 选择“通过”或“驳回”。
3. 驳回时必须填写清楚、可执行的原因。
4. 点击确认提交审核结果。
5. 已通过但审核有误时，可以点击“弃审”并填写原因，预约退回待审核。
6. 弃审不会删除预约单，会保留状态变更历史并允许重新审核。

审核前系统会再次检查预约冲突等关键规则，页面校验结果不能代替后端校验。

### 5.3 使用教师智能助手

1. 打开“智能助手”菜单。
2. 输入“查看本班待审核预约”“统计本班平均信用分”或“哪些学生没有有效安全考试”等问题。
3. 助手可以整理审核依据，但不能直接通过、驳回或弃审。
4. 最终审核必须在“预约审核”页面确认。

## 6. 管理员操作

### 6.1 维护实验室

1. 打开“实验室档案”。
2. 新增或修改实验室编号、名称、类型、位置、容量、开放时间、安全等级、预约模式和状态。
3. 实验室停用后不能再用于新预约，历史记录仍保留。
4. 调整开放时间或容量前，应评估已经存在的预约。

### 6.2 维护设备

1. 打开“设备档案”。
2. 新增或修改设备编号、名称、类型、所属实验室、数量和状态。
3. 正确设置是否需要培训。
4. 维护或停用设备不能被新的预约选择。
5. 删除前确认没有有效预约或业务记录引用。

### 6.3 配置实验室准入和班级负责人

1. 打开“实验室准入”维护准入对象。
2. 按院系、班级或具体学生配置允许预约范围。
3. 打开“班级负责人”配置班级负责人。
4. 班级负责人可以发起班级预约，但仍需满足全部预约规则。

### 6.4 维护安全考试

1. 打开“题库管理”，新增或修改安全题目、选项、正确答案、题型和状态。
2. 打开“安全考试记录”查看学生成绩和有效期。
3. 考试配置包含题目数量、通过分数、有效期等参数，修改前应确认影响范围。

### 6.5 处理信用分与违规

1. 打开“违规记录”。
2. 新增违规时选择学生、关联预约、违规类型和说明。
3. 系统按规则生成信用变动和流水。
4. 违规有误时可以撤销，系统回补对应信用分。
5. 打开“信用分流水”可以查看学生信用变动原因；管理员也可以按制度手工调整。

### 6.6 维护耗材和库存

1. 打开“耗材库存”。
2. 新增耗材并设置所属实验室、单位、初始库存和最低库存。
3. 库存发生变化时点击“调整库存”，填写变动方向和原因。
4. 不要直接修改库存字段；所有变化应通过调整库存或领用审核产生。
5. 打开“库存流水”核对入库、出库、领用和取消归还记录。
6. 打开“耗材领用”查看全部学生申请。
7. 进入待审核领用详情，选择通过或驳回。
8. 通过前确认库存充足；驳回时必须填写原因。

库存不足的耗材会以低库存状态提示。预约取消时，已通过领用会自动归还库存。

### 6.7 管理 Agent 知识库

1. 打开“Agent知识库”。
2. 在文档列表中查看标题、分类、知识类型、可见角色和状态。
3. 新增文档时选择“安全知识”或“平台帮助”。
4. 设置可见角色：全部、学生、教师或管理员。
5. 为文档添加可检索片段，填写关键词和正文。
6. 修改后立即影响后续知识检索，无需重建外部向量库。
7. 不再使用的内容应停用或删除，避免错误知识进入回答。

知识片段应使用明确、可核验的短段落。安全问题应写清场景、操作步骤和禁止事项；平台帮助应写清页面入口和操作顺序。

### 6.8 查看 Agent 审计

1. 打开“Agent审计”。
2. 查看平台会话和消息记录，并按用户或会话标题筛选。
3. 使用工具调用列表查看工具名称、参数、结果、成功状态和耗时。
4. 通过关联消息定位本次回答使用了哪些业务查询。
5. 审计页面只对具有审计权限的管理员开放。

审计记录用于排查无依据回答、权限问题、工具参数错误和业务数据异常，不应把真实密钥等敏感内容写入工具参数或知识片段。

### 6.9 运行 Agent 评测

1. 打开“Agent评测”。
2. 查看当前评测用例和历史上传结果。
3. 选择离线评测可以稳定回归意图、工具、RAG 和边界规则。
4. 选择真实模型评测需要已配置 DeepSeek Key，并会产生实际模型调用费用。
5. 查看意图命中、工具命中、RAG 命中、回答质量和失败用例。
6. 修改提示词、工具或知识库后重新运行，比较前后指标。

## 7. 智能助手使用

### 7.1 创建和切换会话

1. 打开“智能助手”菜单。
2. 点击新建会话。
3. 在左侧选择历史会话继续提问。
4. 点击删除按钮可以删除本人会话。
5. 输入文字后按 Enter 发送，按 Shift+Enter 换行。

### 7.2 推荐提问方式

学生示例：

- “现在还能预约哪些计算机实验室？”
- “我想预约明天下午的电子实验室，预计 6 人。”
- “我通过安全考试了吗？信用分够不够预约？”
- “查看我最近的预约，为什么被驳回？”
- “酒精灯打翻着火怎么处理？”
- “设备档案页面保存哪些数据？”

教师示例：

- “查看本班待审核预约。”
- “统计本班平均信用分。”
- “哪些学生没有有效安全考试？”
- “整理这个预约的审核依据。”

管理员示例：

- “查看当前待审核预约。”
- “统计全校平均信用分。”
- “这个 Agent 知识库是什么？”
- “设备档案保存哪些数据？”

### 7.3 使用预约草稿

1. 学生提供实验室、日期、时段、参与人数、实验名称和所需设备。
2. 条件不完整时，助手会继续询问缺少的条件。
3. 条件完整后，助手生成待确认预约卡片。
4. 核对卡片中的实验室、时间、人数和设备。
5. 点击卡片上的“确认提交预约”。
6. 后端重新执行资格、冲突和设备校验后才创建预约。

助手不能绕过页面直接提交预约。如信息有误，点击取消草稿，补充条件后重新生成。

### 7.4 知识库检索

1. 在智能助手页面点击“知识库”。
2. 输入安全或平台使用问题。
3. 查看命中的文档标题、片段和相似度信息。
4. 该功能不依赖大模型，可用于检查知识库是否有正确资料。
5. 如果没有命中，管理员应检查关键词、正文、知识类型、可见范围和启停状态。

### 7.5 主题与显示

智能助手支持清爽实验室、奶油糖果和薄荷实验室三种主题。主题只改变前端显示，不影响模型回答和权限。

## 8. 管理员配置 DeepSeek

### 8.1 本地配置文件方式

在 `api/ruoyi-admin/application-local.yml` 中填写：

```yaml
bishe:
  ai:
    deepseek-api-key: "在此填写本地 Key"
```

该文件已被 Git 忽略。填写后重启后端。

### 8.2 环境变量方式

在后端启动配置中增加：

```text
DEEPSEEK_API_KEY=在此填写本地 Key
```

环境变量优先于本地配置文件。重启后端后，用管理员账号进入智能助手，点击“测试模型连接”。

### 8.3 未配置 Key 时的状态

- 管理员能看到配置提示和填写位置。
- 学生和教师只看到“助手服务暂未就绪”的业务提示，不显示技术配置。
- 会话、知识库检索、审计和离线评测仍可使用。
- 真实模型对话和真实模型评测需要有效 Key。

禁止把真实 Key 写入源码、SQL、截图、聊天记录或 Git 提交。

## 9. 本地启动步骤

### 9.1 前置条件

- JDK 21
- Maven 3.6+
- Node.js 20+，推荐 22
- MySQL 8，数据库 `bishe_schema`
- Redis 6379

### 9.2 准备运行资源

每次在 IDE 或 JRebel 启动前执行：

```powershell
cd D:\bishe_project\api
mvn -q -pl ruoyi-admin -am process-resources
```

确认以下文件均存在：

```powershell
Test-Path ruoyi-admin\target\classes\application.yml
Test-Path ruoyi-admin\target\classes\mybatis\mybatis-config.xml
Test-Path ruoyi-admin\target\classes\i18n\messages.properties
Test-Path ruoyi-biz\target\classes\mapper\module\RoomMapper.xml
```

### 9.3 启动后端

```powershell
cd D:\bishe_project\api
mvn spring-boot:run -pl ruoyi-admin
```

后端默认地址为 `http://localhost:8087`。确认控制台显示监听 8087 且没有 `Application run failed`。

### 9.4 启动前端

```powershell
cd D:\bishe_project\ui
npm install
npm run dev
```

按 Vite 输出打开页面，本地通常为 `http://127.0.0.1:8090/admin/`。

### 9.5 数据库与演示数据

首次建立数据库时，必须按照项目规定的顺序执行若依基础脚本、`sql/module_core.sql`、代码生成菜单脚本以及 `sql/module/10` 至 `42` 的增量脚本。脚本之间不要随意调换顺序。

演示数据脚本包括：

- `sql/module/05-module-seed-data.sql`
- `sql/module/12-demo-class-data.sql`
- `sql/module/34-device-expansion.sql`
- `sql/module/42-material.sql`
- 各 Agent 知识库和评测脚本

重新导入表后，需要重跑字典配置和菜单脚本。正式使用前应备份数据库，并清理带有演示标记的业务数据。

## 10. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 登录接口提示公钥错误或 500 | 确认页面通过 RSA 加密密码后提交，不要直接调用明文密码接口 |
| 验证码失败 | 刷新验证码；开发调试时检查 Redis 中 `captcha_codes:<uuid>` 是否一致 |
| 无法连接数据库 | 检查 MySQL、库名、账号口令和 `allowPublicKeyRetrieval=true` |
| 无法连接 Redis | 启动 Redis 并确认监听 6379 |
| 启动时报配置占位符缺失 | 在 `api` 下执行 `process-resources`，确认 `target/classes/application.yml` 存在 |
| 启动时报 MyBatis 配置缺失 | 执行资源拷贝，确认 `mybatis/mybatis-config.xml` 和 Mapper XML 在运行类路径中 |
| 页面缺少菜单 | 检查菜单 SQL、角色授权和当前账号角色，重新登录刷新路由 |
| 学生看不到实验室档案 | 学生菜单默认只提供预约专用资源查询，这是权限设计，不是故障 |
| 助手提示服务未就绪 | 管理员检查 DeepSeek Key、后端重启状态和模型连接测试 |
| 助手能检索知识但不能聊天 | 知识检索不依赖模型；聊天还需要有效 DeepSeek Key |
| 预约草稿卡片消失 | 刷新待确认草稿；重新生成前先确认会话和预约条件 |
| 教师审核列表为空 | 检查教师负责部门、待审核预约状态和数据范围 |
| 耗材领用无可选预约 | 只有本人待审核或已通过预约可供申请 |
| 耗材无法删除 | 检查是否存在领用或库存记录引用 |

## 11. 操作注意事项

1. 预约、审核、信用调整、库存调整和知识库修改都属于关键业务操作，执行前应核对对象和数量。
2. 驳回预约和领用时必须填写明确原因，便于学生修正。
3. 不要用一个账号代替多个角色操作，否则审计记录中的操作人身份会失真。
4. 智能助手回答和评测结果不能替代数据库中的真实业务状态。
5. 演示前应检查 Redis、MySQL、后端、前端和模型 Key 是否正常。
6. 演示结束后按本地开发规范清理测试预约、测试耗材和临时知识数据。
7. 数据库备份、真实账号信息和 DeepSeek Key 不得放入公开提交包。

## 12. 答辩演示建议

建议使用一条连续业务线演示，不要只展示互相孤立的页面：

1. 学生登录并检查安全考试与信用分。
2. 使用智能助手查询当前可约实验室和设备。
3. 生成预约草稿并在预约页面确认。
4. 教师登录，查看待审核预约和申请人资质，完成审核。
5. 学生签到、结束实验，查看预约状态日志和信用变化。
6. 学生提交耗材领用，管理员审核并展示库存流水。
7. 管理员查看 Agent 审计和离线评测，说明角色隔离、工具边界和 RAG 来源。

这条演示线能同时覆盖系统业务、权限控制、AI 能力、可追溯性和异常校验。
