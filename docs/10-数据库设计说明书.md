# 校园实验室智能预约与安全管理平台数据库设计说明书

## 1. 数据库范围

- 数据库：MySQL 8
- 库名：`bishe_schema`
- 字符集：`utf8mb4`
- 完整初始化文件：`sql/release/01-bishe_schema_full.sql`
- 核心建表文件：`sql/module_core.sql`
- 增量脚本：`sql/module/`

当前正式命名不使用 `lab_` 前缀，也不使用 `created_at`、`updated_at` 作为业务表审计字段；业务表统一使用 `create_by`、`create_time`、`update_by`、`update_time`、`remark`。

## 2. 若依基础表

数据库同时包含若依系统表：

- `sys_user`、`sys_role`、`sys_user_role`
- `sys_dept`、`sys_post`、`sys_user_post`
- `sys_menu`、`sys_role_menu`、`sys_role_dept`
- `sys_dict_type`、`sys_dict_data`
- `sys_config`、`sys_notice`
- `sys_oper_log`、`sys_logininfor`
- Quartz 调度表
- `magic_api_file`、`magic_backup_record`
- `biz_region`

业务代码不直接修改若依安全框架，只扩展现有权限和菜单模型。

## 3. 核心业务表

| 表 | 作用 | 关键关系 |
| --- | --- | --- |
| `room` | 实验室档案 | 被设备、预约、准入和耗材引用 |
| `device` | 设备档案 | `room_id` 外键指向 `room` |
| `reservation` | 预约主表 | 关联申请人和实验室 |
| `reservation_device` | 预约设备明细 | 关联预约和设备，保存使用数量 |
| `reservation_review` | 审核记录 | 关联预约和审核教师 |
| `safety_exam_record` | 安全考试成绩 | 关联学生，保存成绩和有效期 |
| `credit_record` | 信用流水 | 关联用户，保存变动值和余额 |

## 4. 准入与班级预约

| 表 | 作用 |
| --- | --- |
| `room_access` | 实验室院系、班级或学生准入范围 |
| `class_representative` | 班级负责人及班级预约资格 |

`room` 同时保存 `reservation_mode`、`dept_id` 等扩展字段。班级预约仍使用 `reservation`，通过预约类型和申请人身份区分。

## 5. 生命周期与信用安全

| 表 | 作用 |
| --- | --- |
| `reservation_status_log` | 预约创建、审核、取消、签到、完成和爽约日志 |
| `credit_account` | 学生当前信用账户 |
| `violation_record` | 爽约、临近取消、安全违规和设备损坏记录 |

预约状态编码：

| 值 | 状态 |
| --- | --- |
| `0` | 待审核 |
| `1` | 已通过 |
| `2` | 已驳回 |
| `3` | 已取消 |
| `4` | 已完成 |
| `5` | 已签到 |
| `6` | 已爽约 |

## 6. 安全考试

| 表 | 作用 |
| --- | --- |
| `safety_exam_config` | 题目数量、通过分、有效期等配置 |
| `safety_question` | 安全考试题库 |
| `safety_exam_answer` | 一次考试中的答题明细 |
| `safety_exam_record` | 考试结果、通过状态和有效期 |

## 7. 耗材库存

| 表 | 作用 |
| --- | --- |
| `material` | 耗材档案和当前库存 |
| `material_apply` | 预约耗材领用申请 |
| `material_stock_record` | 初始入库、手工调整、领用出库和取消归还流水 |

库存只允许通过业务服务变化：

- 管理员手工调整库存。
- 领用审核通过扣减库存。
- 预约取消时关闭待审核申请或归还已通过领用。

## 8. Agent 与 RAG

| 表 | 作用 |
| --- | --- |
| `chat_session` | Agent 会话 |
| `chat_message` | 用户和助手消息 |
| `tool_call_log` | 工具名称、参数、返回、状态、耗时和消息关联 |
| `reservation_draft` | 待确认预约草稿 |
| `knowledge_document` | 安全知识或平台帮助文档 |
| `knowledge_chunk` | 可检索知识片段 |
| `agent_eval_case` | 离线与真实模型评测用例 |
| `agent_eval_run` | 一次评测运行及指标 |
| `agent_eval_result` | 单条用例结果 |

知识文档通过 `knowledge_type` 和 `audience` 控制知识类型及角色可见范围。

## 9. 关键约束

1. 同一实验室的有效预约不能时间重叠。
2. 预约开始时间必须早于结束时间。
3. 参与人数不能超过实验室容量。
4. 设备必须属于预约实验室，使用数量不能超过设备数量。
5. 高风险或要求考试的实验室必须有有效考试记录。
6. 信用分低于门槛时不能提交预约。
7. 购物车式的重复设备明细通过唯一键约束。
8. 已通过或已签到的预约不能直接删除。
9. 库存变化必须大于零并生成流水。
10. 会话、消息、工具日志和草稿均校验当前用户归属。

## 10. 初始化与升级

新设备推荐一次性导入：

```text
sql/release/01-bishe_schema_full.sql
```

该文件包含若依基础库、Magic API、行政区划、业务表、演示数据、菜单角色和全部 Agent 数据。

已有数据库做局部升级时，按 [AGENTS.md](../AGENTS.md) 和 [代码生成与模块落地说明](05-代码生成与模块落地说明.md) 的顺序执行增量脚本。

当前系统核心数据不是统计总数，而是初始化自检结果：5 个实验室、30 台设备、58 篇知识文档、138 个知识片段和 60 条评测用例。
