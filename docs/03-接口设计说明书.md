# 校园实验室智能预约与安全管理平台接口设计说明书

## 1. 接口总则

| 项目 | 约定 |
| --- | --- |
| 后端基础地址 | `http://localhost:8087` |
| 前端开发代理 | `/dev-api` 转发到后端 |
| 数据格式 | JSON；导出接口为 Excel |
| 字符编码 | UTF-8 |
| 认证 | JWT，请求头 `Authorization: Bearer <token>` |
| 成功响应 | 若依 `AjaxResult` |
| 分页响应 | 若依 `TableDataInfo` 或 MyBatis-Plus 分页结构 |
| 分页参数 | `pageNum`、`pageSize` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |

所有业务接口都要求登录，并通过 `@PreAuthorize` 检查权限。普通 CRUD 仅作为数据维护能力，预约、考试、信用扣减和库存变化必须走对应业务接口。

### 3.3 教师审核

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/module/reservation/review/pending` | `module:reservation:review` | 查询教师负责范围待审核预约 |
| POST | `/module/reservation/review/{id}` | `module:reservation:review` | 审核预约 |
| POST | `/module/reservation/updateStatus` | `module:reservation:review` | 统一通过、驳回或弃审 |
| POST | `/module/reservation/{id}/no-show` | `module:reservation:review` | 手动标记爽约 |

审核请求示例：

```json
{
  "action": "APPROVE",
  "comment": "资质和设备符合要求"
}
```

实际实现根据前端调用接口读取状态动作，驳回时必须填写原因。后端会重新检查状态机和预约冲突。

## 11. 错误与测试要求

业务异常通过 `ServiceException` 转换为用户可理解的消息，例如时间冲突、容量超限、未通过安全考试、信用分不足、库存不足和无权限。

接口测试至少覆盖：

1. 正常参数和成功响应。
2. 缺少参数、非法 ID 和时间格式错误。
3. 未登录、无权限和跨角色访问。
4. 预约时间冲突、容量、准入、考试和信用门槛。
5. 重复审核、重复签到、状态机非法流转。
6. 耗材库存不足、重复审核和预约取消归还。
7. Agent 会话归属、工具白名单、知识可见范围和写操作边界。
