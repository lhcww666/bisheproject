## Context

智能助手已经按学生、教师、管理员创建三套 ChatClient 和工具白名单，也有安全知识 RAG、预约草稿及审计基础。本次在既有结构上优化表达、知识范围和交互状态，不替换 Spring AI 或业务 Service。

## Goals / Non-Goals

- Goals: 消除普通用户可见的技术术语；让平台帮助可回答；改善预约复合问题的下一步引导；保证预约写操作只在页面确认。
- Non-Goals: 不引入外部向量数据库；不重写现有权限、冲突校验和预约生命周期；不开放管理员审核写操作给模型。

## Decisions

- Decision: 公共提示词只保留角色无关的业务约束，技术术语和管理员诊断能力放入管理员提示词。
- Decision: 知识文档增加 `knowledgeType` 与 `audience`，检索时按当前登录角色过滤；安全知识默认 `SAFETY/ALL`，平台帮助使用 `PLATFORM`。
- Decision: 新增平台帮助查询工具，复用现有混合检索，不新建独立 RAG 管道。
- Decision: 从学生工具白名单移除 `confirmReservation`，模型只能创建草稿，确认提交由页面接口完成。
- Decision: 预约条件通过提示词和评测约束缺失项收集，复用现有会话历史与草稿数据，不新增会话状态表。

## Risks / Trade-offs

- 关键词检索对平台帮助问题的召回有限 -> 为平台帮助补充人工关键词并增加固定评测用例。
- 增加 `audience` 字段可能影响旧数据 -> 迁移脚本为已有数据补 `SAFETY/ALL` 默认值。
- 依赖提示词仍可能遗漏条件 -> 以多轮评测和草稿服务校验作为最终保障。

## Migration Plan

1. 执行新的增量 SQL 脚本，为知识文档补充类型和可见范围，并写入平台帮助资料。
2. 发布后端与前端改动。
3. 运行角色化离线评测与页面验证。

## Open Questions
