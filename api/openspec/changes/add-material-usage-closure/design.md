## Context

耗材领用跨预约、库存和角色数据范围。领用申请必须绑定申请人本人的有效预约，审核通过后扣减耗材库存，预约取消时归还库存。两名管理员同时审核或学生取消预约时，扣减和归还都必须保持原子性。

## Goals / Non-Goals

- Goals: 建立可追溯的最小耗材业务闭环；保证库存不为负；按角色隔离维护、申请和审核权限。
- Non-Goals: 不加入采购、批次、有效期、报废、多明细申请或 Agent 自动领用能力。

## Decisions

- Decision: 一个耗材申请只包含一种耗材，使用 `apply_quantity` 表示申请数量，简化并发扣减与取消归还。
- Decision: 库存变化统一写入 `material_stock_record`，记录类型为 `INITIAL`、`ADJUST_IN`、`ADJUST_OUT`、`APPLY_OUT`、`CANCEL_RETURN`。
- Decision: 审核和取消归还先锁定申请与耗材行，再执行带库存下限的条件更新；影响行数为 0 时不得产生负库存。
- Decision: 耗材档案编辑不直接改动库存，库存只能通过专门的调整动作变更。
- Decision: 申请状态使用 `PENDING`、`APPROVED`、`REJECTED`、`CANCELED`、`RETURNED`，通过字典展示。

## Risks / Trade-offs

- 同一耗材可能有多条待审核申请，申请时库存充足不代表审核时仍充足；审核阶段必须再次校验并支持库存不足自动驳回。
- 耗材已有申请或流水时禁止删除，以保留审计链；停用耗材通过状态字段完成。
- 预约与耗材模块存在事务协作，但通过服务接口单向依赖，避免 Spring Bean 循环依赖。
